# WEAVIA API Reference

**Smart India Hackathon 2026 · SIH26081 · Ministry of Earth Sciences (MoES)**

Base path: `/api/v1`. Interactive docs: `http://localhost:8000/docs` (Swagger UI, generated by FastAPI).

The API reads stored pipeline artifacts only. Run the pipeline first, or routes return an error.

```bash
cd backend
python -u -W ignore -c "from weavia.pipeline import run; run('data', days=1095)"
uvicorn weavia.api.main:app --port 8000
```

> Data is **synthetic**. Every response that carries provenance includes `data_mode` and a `data_notice`. Do not present these values as real forecasts.

## Conventions

| Item | Rule |
|---|---|
| `issue` | `YYYY-MM-DD`. Optional. Defaults to the latest issue. Only dates in the served (test-slice) range are valid |
| `lead` | Hours. One of `6, 12, 24, 48, 72`. Default `24` |
| `variable` | One of `rain`, `temp`, `wind`. Default `rain` |
| `location_id` | Station id, for example `blr`. Full list in `GET /meta` |
| Models | `model_a`, `model_b`, `model_c`, `model_d` |
| Units | rain `mm/6h`, temp `degC`, wind `km/h` |

### Errors

| Code | Meaning |
|---|---|
| 404 | Unknown location, issue date outside served range, or unknown event id |
| 422 | Invalid `lead`, `variable`, or lab weights |
| 429 | Rate limit exceeded. Honour the `Retry-After` header (seconds) |
| 503 | Artifacts missing. Run the pipeline. `GET /health` reports this as `status: no_artifacts` instead of failing |

## Routes

| Method | Route | Purpose |
|---|---|---|
| GET | `/health` | Service and artifact status |
| GET | `/meta` | Provenance, issue dates, leads, variables, models, regimes, locations |
| GET | `/map` | All-location snapshot that drives every globe layer |
| GET | `/overview` | National headline: ranked alerts and weight flow |
| GET | `/forecast` | Blended forecast with uncertainty, disagreement, regime |
| GET | `/timeline` | One location across all leads, with interval and observed value |
| GET | `/trust` | Per-model weights and the reasons behind them |
| GET | `/regime` | Regime label, confidence, probabilities, classifier verification |
| GET | `/explain` | Full explanation for one forecast |
| GET | `/skill-atlas` | Verified MAE per model × regime and per region |
| GET | `/verification` | Test-slice results with confidence intervals |
| GET | `/events` | Extreme-event and large-miss list |
| GET | `/autopsy/{event_id}` | Forecast failure analysis for one event |
| POST | `/lab/simulate` | Counterfactual weights, with back-test |

---

### `GET /health`

No parameters.

```json
{ "status": "ok", "model_version": "weavia-meta-lgbm-0.1", "data_mode": "synthetic" }
```

### `GET /meta`

No parameters. Returns:

- `provenance`: `data_mode`, `data_notice`, `model_version`, `generated_at`
- `issues`, `latest_issue`
- `leads`
- `variables`: label, unit, `event_threshold` for each
- `models`, `regimes`
- `locations`: `id`, `name`, `lat`, `lon`, `region`, `coastal`

### `GET /map`

| Param | Default |
|---|---|
| `issue` | latest |
| `lead` | 24 |

Returns `issue_time`, `lead_h`, `valid_time`, `units`, `points`, `weight_flow`.

Each point in `points`:

| Field | Meaning |
|---|---|
| `location_id`, `name`, `lat`, `lon`, `region` | Station |
| `regime`, `regime_confidence` | Predicted regime |
| `risk`, `risk_variable` | Highest event probability across variables, and which variable |
| `top_model` | `{model_id, name, weight}` of the most trusted model |
| `weights` | Weight per model, averaged across variables |
| `vars` | Per variable: `value`, `p10`, `p90`, `confidence`, `spread`, `event_prob` |

`weight_flow` is the mean weight per model across all locations.

### `GET /overview`

Params: `issue`, `lead`. Returns the 12 highest alerts ranked by event probability, `alert_thresholds`, `weight_flow`, `provenance`. Each alert has `above_alert_threshold`.

### `GET /forecast`

Params: `location_id` (required), `variable`, `issue`, `lead`. Returns `case`, `forecast`, `disagreement`, `regime`, `provenance`.

### `GET /timeline`

Params: `location_id` (required), `variable`, `issue`. Returns a `series` over all leads. Each row has `blend`, `p10`, `p90`, `equal` (equal-weight baseline), `observed` (for verification only), `confidence`, `event_prob`, per-model `models` and `weights`.

### `GET /trust`

Params: `location_id` (required), `variable`, `issue`, `lead`. Returns `case`, `models` (weights and reasons), `meta_model_tau`.

### `GET /regime`

Params: `location_id` (required), `issue`, `lead`. Returns `label`, `confidence`, `probabilities` for all 8 regimes, `observed_regime`, `classifier_verification`.

### `GET /explain`

Params: `location_id` (required), `variable`, `issue`, `lead`. Returns the full explanation object used by the Why view.

### `GET /skill-atlas`

Params: `variable`, `lead`. Returns `cells` (regime × model: `mae`, `bias`, `n`), `by_region`, `models`, `regimes`. Computed from training-period error memory.

### `GET /verification`

No parameters. Returns `provenance`, `verification` (all results and CIs), `splits`. See [VERIFICATION.md](VERIFICATION.md).

### `GET /events`

| Param | Default |
|---|---|
| `variable` | all |
| `limit` | 40 |

### `GET /autopsy/{event_id}`

Param: `lead` (default 24). A lead outside the supported autopsy leads returns 422. Unknown `event_id` returns 404. Event ids come from `GET /events`.

### `POST /lab/simulate`

Body:

```json
{
  "location_id": "blr",
  "variable": "rain",
  "issue": null,
  "lead": 24,
  "weights": { "model_a": 0.2, "model_b": 0.5, "model_c": 0.3, "model_d": 0.0 },
  "scope": "global",
  "same_regime": false
}
```

| Field | Rule |
|---|---|
| `weights` | Non-negative. Must have a positive sum. Normalized by the server |
| `scope` | `global`, `region`, or `location` |
| `same_regime` | Restrict the back-test to cases in the same regime |

Returns the simulated forecast and a back-test of the same fixed weights on the held-out test slice.

## Examples

```bash
curl "http://localhost:8000/api/v1/health"
curl "http://localhost:8000/api/v1/map?lead=24"
curl "http://localhost:8000/api/v1/forecast?location_id=blr&variable=rain&lead=24"
curl "http://localhost:8000/api/v1/timeline?location_id=blr&variable=temp"
curl -X POST "http://localhost:8000/api/v1/lab/simulate" \
  -H "Content-Type: application/json" \
  -d '{"location_id":"blr","variable":"rain","lead":24,"weights":{"model_a":1,"model_b":1,"model_c":1,"model_d":1}}'
```

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `WEAVIA_DATA` | `data` | Artifact directory the API reads |
| `WEAVIA_CORS` | `*` | Comma-separated allowed origins. Restrict before any public deployment |
| `WEAVIA_RATE_LIMIT` | `120` | Requests per minute per client, all routes except `/health`. `0` disables |
| `WEAVIA_LAB_RATE_LIMIT` | `20` | Requests per minute per client for `POST /lab/simulate`. `0` disables |
| `WEAVIA_TRUST_PROXY` | off | Set `1` when a proxy (including the Next.js rewrite) sits in front of the API. Without it every user shares the proxy's single limit bucket |
| `WEAVIA_PROXY_HOPS` | `1` | Trusted proxies in front of the API. The client is read from `X-Forwarded-For` counted from the right, so client-supplied entries on the left cannot spoof the limit |

The limiter is in-memory and per process. Responses carry `X-Content-Type-Options`, `X-Frame-Options` and `Referrer-Policy` headers.
